# Лаборатория нестабильных порталов

Веб-приложение для смотрителя лаборатории, где открываются магические порталы.
Смотритель видит список порталов, понимает уровень риска (по объяснимой формуле) и
принимает решения: стабилизировать, закрыть, отправить наблюдателя, пометить «под
вопросом». Все действия проходят через проверку «невозможных состояний» и попадают
в журнал.

Стек: **Vite + React 18 + TypeScript**, тесты — **Vitest**. Состояние хранится в
памяти (без бэкенда), секретов в коде нет.

**Живая версия:** https://sasha1ooo.github.io/unstable-portals/
(деплой GitHub Pages из этой же ветки, `npm run build`).

## Как запустить

### Вариант A. Готовый файл (без Node)

Распакуйте **`portal-lab-app.zip`** из корня репозитория и запустите
**`Запустить.bat`** (Windows) / **`Запустить.command`** (macOS) — или просто
откройте `index.html` в браузере. Это самодостаточная сборка: весь JS/CSS внутри
одного файла, Node и интернет не нужны.

Пересобрать архив: `npm run pack` (создаёт `portal-lab-app.zip` заново).
Из корня репозитория dev-режим также поднимает `Запуск-из-исходников.bat`.

### Вариант B. Из исходников (режим разработки)

Нужен Node.js ≥ 18.

```bash
npm install
npm run dev       # http://localhost:5173
```

Прочие команды:

```bash
npm test          # прогнать 44 юнит-теста (домен: риск, действия, редьюсер, сводка)
npm run build     # собрать dist/index.html (один файл)
npm run preview   # посмотреть собранную версию, http://localhost:4173
```

## Что внутри

Приложение — три вкладки:

| Вкладка | Что там |
|---|---|
| **Панель смотрителя** | сводка, сценарии, таблица порталов, карточка портала, журнал событий |
| **AI Worklog** | как делалось приложение: инструменты, этапы, решения, ошибки AI |
| **Чеклист** | какие сценарии проверены вручную перед сдачей |

**Быстрый прогон на панели:**

1. Кликните портал в таблице → справа откроется карточка с разбором риска, историей
   и действиями.
2. Блок **«Сценарии и наборы данных»** переключает состояние приложения:
   демо-набор · пустой список · критический портал · случайный портал · сброс.
3. Нажмите заблокированное действие (🔒) — увидите отказ и запись в журнале.
4. Стабилизируйте «Грозовые врата» — уровень риска понизится, это отразится
   в истории портала и в журнале.

## Модель портала

| Поле | Смысл |
|---|---|
| `name`, `destinationWorld` | название и мир назначения |
| `energy` (0–100) | уровень энергии портала |
| `stability` (0–100) | стабильность (100 — идеально стабилен) |
| `minutesToCollapse` | время до схлопывания, минуты |
| `creaturesInside` | сколько существ сейчас внутри |
| `status` | `open` · `under_review` (под вопросом) · `closed` |
| `hasObserver` | отправлен ли наблюдатель |
| `history[]` | история изменений конкретного портала |

## Формула риска

Реализация — [`src/domain/risk.ts`](src/domain/risk.ts). Каждый фактор приводится к
шкале 0–100 и умножается на вес; сумма весов = 1, поэтому итог тоже 0–100.

```
score = 0.45 · (100 − stability)      // нестабильность
      + 0.30 · energy                  // энергия
      + 0.15 · timePressure            // дефицит времени
      + 0.10 · creaturePressure        // существа внутри (цена ошибки)

timePressure     = clamp(100 − minutesToCollapse, 0, 100)   // <100 мин начинает давить
creaturePressure = min(creaturesInside, 10) / 10 · 100
```

Пороги уровней: `<25` низкий · `25–49` средний · `50–74` высокий · `≥75` критический.

Жёсткие правила (override) поверх счёта:

- `minutesToCollapse ≤ 10` → риск не ниже **высокого**;
- `stability < 15` и `energy > 80` → **критический** (каскадный разрыв).

Закрытый портал риска не несёт (`none`). Разбор слагаемых показывается прямо
в карточке портала.

## Действия и «невозможные состояния»

Единственный источник правды — `canRun(action, portal)` в
[`src/domain/actions.ts`](src/domain/actions.ts). Его вызывает и UI (вид кнопки), и
редьюсер (защита на уровне состояния). Результат: «можно» / «жёстко нельзя» /
«нужно подтверждение».

| Действие | Запрещено (жёстко) | Требует подтверждения |
|---|---|---|
| **Стабилизировать** | портал закрыт; стабильность ≥ 95 | — |
| **Закрыть портал** | уже закрыт | внутри есть существа |
| **Отправить наблюдателя** | портал закрыт; наблюдатель уже на месте; **критический риск** | высокий риск |
| **Пометить «под вопросом»** | портал закрыт; уже помечен | — |
| **Снять «под вопросом»** | портал не помечен | — |

Заблокированную кнопку видно (🔒) и по ней можно нажать — попытка фиксируется в
журнале как «отклонено». Так проверяется обязательный сценарий «попытка запрещённого
действия».

Эффект стабилизации: стабильность +25, энергия −12, время +20 мин (с обрезкой по 0–100).

## Журнал и сводка

- **Журнал событий** — все действия, отказы и системные события; новые сверху;
  фильтры «действие / отклонено / система».
- **Итоговая сводка** — сколько порталов открыто / под вопросом / закрыто / с
  критическим риском / с наблюдателем, плюс список «Внимание в первую очередь»
  (активные порталы, отсортированные по убыванию риска).

Блоки с длинными списками имеют фиксированную высоту с внутренней прокруткой, а
раскладку рабочей области можно перекраивать за полосы-разделители (двойной клик
по полосе — сброс, размеры хранятся в `localStorage`):

- **между колонками** (правый край списка / левый край карточки и истории) — ширина
  колонок;
- **между карточкой портала и историей** — как поделить высоту между ними (общая
  высота колонки не меняется);
- **нижний край списка порталов или правой колонки** — их общая высота (список и
  колонка всегда равны); при большом числе порталов появляется прокрутка, а не рост
  панели (шапка таблицы «прилипает» при прокрутке);
- **нижний край журнала событий** — высота журнала;
- **«Внимание в первую очередь»** в сводке — прокручивается, высоту можно менять за
  правый нижний угол (нативный `resize`).

## Тесты

```bash
npm test
```

44 юнит-теста ([`src/domain/*.test.ts`](src/domain)):

- `risk.test.ts` — слагаемые формулы, пороги, оба override, закрытый портал;
- `actions.test.ts` — каждый запрет и каждое подтверждение, эффекты действий;
- `reducer.test.ts` — пустой список, заблокированное действие в журнале, изменение
  риска после стабилизации, порядок журнала после нескольких операций;
- `summary.test.ts` — счётчики и сортировка «Внимание в первую очередь»;
- `text.test.ts` — склонение числительных;
- `seed.test.ts` — генератор случайного портала (границы полей, детерминизм по ГПСЧ).

Ручные сценарии — вкладка **«Чеклист»** в приложении.
